# Authenticator codes (TOTP)

An authenticator app (Google Authenticator, Microsoft Authenticator, Authy, or the one built into a password manager) generates a six-digit code that changes every 30 seconds. It is a real second factor and a large step up from text messages, but it is **not phishing-resistant**: the code is still something you type, and anything you can type, you can be tricked into typing on the wrong site.

* **Shared secret:** when you scan the QR code at setup, the site and your app each store the same secret. Both compute the same code from that secret plus the current time. Nothing travels over the phone network.
* **The code:** a six-digit hash of the secret and the time, valid for about 30 seconds, and usually accepted for a window on either side.
* **The secret is the key:** anyone who has it can generate your codes forever. The QR code, a screenshot of it, and the app's backup file all contain it.
* **Cloud backup:** apps that sync the secret to Google, Microsoft, or Authy's servers make it recoverable, and make that account the new weakest link.
* **No phishing resistance:** a fake site can ask for your code and relay it to the real site within the 30 seconds. This is automated and common.
* **Push approvals:** "tap Approve" prompts are a variant. They are easier and no more phishing-resistant; approving a prompt you did not start is the whole attack.
* **Where it fits:** better than a text on every account. For an account holding real money, use it only where a passkey or hardware key is not offered, and never as the recovery path for a stronger method.
